Settings guide

Mouse settings that change your test results

The same mouse can produce different numbers on two different machines. Four settings explain almost all of that — and none of them are on the mouse.

Written by Mark · Updated 28 October 2026

The same mouse, in the same hand, on two different machines, can produce two different sets of numbers. Almost all of that difference comes from four settings — and none of them are on the mouse.

This guide is the one to read when a result looks wrong and you are not sure whether the mouse is at fault. Change one setting, run the test again, and compare. That turns a vague feeling into an experiment.

Pointer speed

Pointer speed — the setting that changes every accuracy score

On Windows 11 the pointer speed slider lives under Settings → Bluetooth & devices → Mouse, and the same page carries the “Enhance pointer precision” toggle. On Windows 10 the equivalent is Settings → Devices → Mouse, and the two classic options are in the legacy dialog under Additional mouse options → Pointer Options tab — the pointer speed slider is under Motion, and “Enhance pointer precision” is the checkbox beneath it.

On macOS the equivalent is System Settings → Mouse → Point & Click → “Tracking speed”, and the acceleration curve is under Advanced → “Pointer acceleration”.

Here is why this matters more than it looks. Pointer speed scales how far the pointer travels for a given physical movement. A high setting means your hand travels less to cross the screen, and the pointer precision test — which asks you to hit a 26 px target — becomes correspondingly harder. Turn the setting down and the accuracy figure rises without the mouse changing at all.

The practical consequence: an accuracy score is meaningless on its own. It is a score for a mouse at a given pointer speed. If you want to compare two mice, set both pointer speeds to the same number first. If you want to know why your accuracy dropped since last week, check the setting before you blame the mouse.

Pointer acceleration

Pointer acceleration — the setting that makes aiming feel wrong

Acceleration means the pointer does not move at a fixed ratio to your hand. It moves further when you move fast and more precisely when you move slowly. On Windows this is “Enhance pointer precision”, on by default. On macOS it is “Pointer acceleration”, also on by default, and Apple's own documentation puts it plainly: by default the pointer moves more quickly for fast movements and more precisely for slow ones.

Acceleration is the reason the pointer precision test can behave like it is punishing you for aiming carefully. You settle on a target, slow down to place the click, and the sensitivity curve hands you a slower response exactly when you have switched to fine control. That is the moment of maximum error, and the curve makes it worse.

It is also the reason the drag test can fail while the click test passes. Dragging is a sustained, slow movement — exactly the regime where the acceleration curve changes most.

The experiment

Run the pointer precision test and note the percentage. Turn “Enhance pointer precision” off (Windows) or “Pointer acceleration” off (macOS), and run it again. If the second number is materially higher, you had been fighting a curve rather than a mouse fault. The drag accuracy test is the sharper signal here: the tool treats a drag offset of under 8 px as “as accurate while dragging as while clicking”, so any drag gap that closes when acceleration is off points at the curve.

Double-click speed

Double-click speed — where Windows and macOS disagree

On Windows the slider is tucked one level deeper than you would expect: Settings → Bluetooth & devices → Mouse → Related settings → Additional mouse settings, then the Buttons tab, then the Speed slider under Double-click speed. The legacy route is Control Panel → Mouse → Buttons tab. The default window is 500 ms.

On macOS there is no millisecond window at all. The setting is System Settings → Accessibility → Pointer Control → “Double-click speed”, and it offers Slow, Medium and Fast rather than a slider.

This is worth knowing if you have moved between the two, because a mouse tuned on one platform routinely feels broken on the other. A muscle memory learned against a 500 ms window is much slower than macOS's Medium setting expects, and the first double-click on a new machine lands as two single clicks.

Display refresh rate

Display refresh rate — the setting that is not about the mouse at all

Hover response measures the delay between the pointer entering a target and the first movement event being delivered. The tool calls anything under 25 ms “instantly” and anything at 60 ms or more slow. On a high-refresh display, that delay is frequently the display’s own frame time rather than anything the mouse did.

So if hover feels sluggish but every other reading is fine, change the monitor’s refresh rate before you open the mouse. A 144 Hz display will report a longer hover delay than a 60 Hz one for an identical mouse, and that is the display answering, not the sensor.

The same effect shows up in motion smoothness. A pointer event that arrives between frames is delivered on the next frame, so a fast display can add apparent jitter to a perfectly healthy mouse.

Put it together

The one-setting experiment

If a reading looks wrong, change one setting and re-run. Do not change two, or you will not know which one did it.

Record the baseline

Run the pointer precision test and the drag accuracy test. Write down both numbers and the pointer speed setting they were taken at.

Change one thing

Start with pointer acceleration, because it is the switch most often left on without anyone knowing it was there.

Re-run, same conditions

Same mouse, same pad, same surface, same twenty targets. The drag test is the sharper of the two, because it is the one that moves when the curve changes.

Decide what you have

If the numbers moved, the setting was the cause and the mouse is fine. If they did not move, the mouse or its surface is the problem — and the symptom guides cover that.
