About

A small lab for the two things you touch all day

InputScope is an independent project. It exists because peripherals degrade quietly, browsers already expose everything needed to measure that degradation, and almost nobody has bothered to build the measuring tools properly.

The name is the idea, more or less: an oscilloscope for the devices you touch all day. Not a scoreboard and not a click counter — a way to see what the hardware is actually doing, and to work out whether a number that feels wrong is a broken switch or a buried setting.

What InputScope is

InputScope is a set of browser-based diagnostic tools for pointing devices and keyboards. Each tool isolates one measurable behaviour of the hardware, presents the raw number, and then explains what that number means in practice. There are fifteen tests across two suites: nine for the mouse, six for the keyboard.

The site is deliberately unfinished. A gamepad, touchpad, headset, display, webcam and printer diagnostic are in development, and they will follow the same rule as everything else here: run locally, upload nothing, and tell you what the number actually means.

The project is deliberately small. It is not a hardware review site, it does not sell anything, and it has no affiliate relationships with any manufacturer. There is no account system and no database. The whole thing is a handful of static pages and some JavaScript that talks to the browser's own input APIs.

How the tests are built

Every test uses a standard web API and nothing else. Pointer tests rely on the Pointer Events interface — pointermove, pointerdown, pointerrawupdate where it is available, and the getCoalescedEvents method. Keyboard tests rely on the Keyboard Events interface, where event.code gives the physical identity of a key independently of the character it produces and event.key gives the character the operating system believes that key should produce.

That distinction is the basis of the layout detection test. A key has a physical position that never changes and a logical character that depends on the selected layout, and comparing the two against known layouts identifies the board regardless of how the system is configured.

Timing measurements use performance.now(), which is monotonic and unaffected by wall-clock adjustments. Where a result cannot be a true measurement — a polling rate in a browser that does not expose raw sampling, for instance — the interface says so in the result panel instead of presenting the estimate as fact.

Editorial policy

Every explanation on this site is written by a human who understands the hardware being described. No text is generated from product listings, no descriptions are copied from manufacturer marketing, and no result is a placeholder for a real measurement.

Where a claim is contested or hardware-dependent, the site says so. This is the main reason InputScope will not tell you your mouse's exact DPI: a browser genuinely cannot read it, and pretending otherwise would make every other number on the site less trustworthy.

If an advertisement ever appears on an informational page, it will be clearly labelled and will not be placed inside a measurement surface, because a layout shift mid-test would corrupt the readings. There will never be an advertisement on the tool pages themselves.

Corrections and updates

Hardware behaves differently across platforms, and a result that reads correctly on one operating system may be misleading on another. If you find something inaccurate, get in touch — corrections are made promptly, and where a page has been revised the change is noted in the log below.

Why the site is built this way

There is a particular kind of frustration in owning a device that is quietly failing. A mouse that needs three clicks to open a menu. A keyboard where one letter comes out wrong every so often. A scroll wheel that skips back. In every case the obvious question — is it the hardware or is it the software? — has no easy answer, because the tools that might answer it do not exist, or are buried in a support article written for a different device.

Building those tools properly turned out to be a manageable amount of work, so it seemed worth putting them somewhere people can find. That is the whole project.
